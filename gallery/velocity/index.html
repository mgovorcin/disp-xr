    Velocity from a trajectory fit¶

    fit_trajectory fits every pixel with a trajectory model: offset and velocity, seasonal sine/cosine pairs, steps and postseismic terms, by least squares over each pixel's valid epochs. The synthetic frame has a known velocity, a 5 mm annual cycle and a 10 mm step, so the fit can be checked.

from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np

from disp_xr.tutorial import make_disp_stack

truth = make_disp_stack(
    folder, "three_ministacks", shape=(64, 64), epochs_per_ministack=70
)
ds = dxr.open_disp(folder).disp.mask("recommended").disp.chain()
print(
    f"{ds.sizes['time']} epochs over "
    f"{(ds.time[-1] - ds.time[0]).values.astype('timedelta64[D]')}"
)

    Fit¶

    Trajectory lists the terms. The coefficient names encode the model, so a fit written to a store can be evaluated again with predict_trajectory.

    Colored-noise and robust sigmas¶

    fit_velocity estimates the noise of every pixel (see "Choosing a velocity method" for when to use which). "whittle" keeps the OLS velocity and estimates power-law plus white noise from the periodogram of the residuals (reliable from about 200 epochs); "midas" takes the median of one-year slopes, with a deliberately conservative sigma. The synthetic noise is white, so OLS and Whittle should agree and Whittle should find kappa near 0; on real InSAR series the white-noise sigma is several times too small.
