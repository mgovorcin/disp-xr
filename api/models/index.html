    Spatial models¶

    Estimators with a fit / predict interface for spatial models: trends, the GNSS tie (T33) will build on them. verde is the design reference, not a dependency.

    from disp_xr import models

flat = ds.disp.deramp(degree=1)  # a plane removed from every epoch, lazily

coords = models.coordinates(points)  # (easting, northing) of a point table
est = models.Chain([("trend", models.Trend(1)), ("spline", models.Spline(1e-6))])
est.fit(coords, points.velocity.values)
grid = est.grid(like=ds)  # on the frame's grid, with its CRS
scores = models.cross_val_score(est, coords, points.velocity.values, spacing=5000)

    Estimator base for spatial models (PRD F9, plan task T19).

    Spatial models (trends, GNSS ties, gridders) share one shape, after verde (the design reference only, not a dependency; PRD decision):

    • fit(coords, data, weights=None) estimates the parameters and returns the estimator; fitted attributes end in _;
    • predict(coords) evaluates the model at any coordinates;
    • score(coords, data, weights=None) is the weighted R²;
    • grid(...) predicts on a regular grid as an xr.DataArray with a CRS;
    • :class:Chain fits steps in sequence, each on the residual of the last.

    Coordinates are a tuple (easting, northing) of arrays of one shape, in the CRS of the data (projected, in meters for DISP frames). :func:coordinates builds them from a raster, a point table or a DataFrame. :func:cross_val_score scores an estimator with spatial block k-fold cross-validation, which keeps neighbors out of each other's folds (Roberts et al. 2017, https://doi.org/10.1111/ecog.02881).

    BaseEstimator ¶

    Base class of disp-xr spatial estimators.

    Subclasses take their parameters as keyword arguments of __init__ (stored under the same names) and implement _fit(easting, northing, data, weights) and _predict(easting, northing) on 1D arrays without NaN; the base class checks inputs, drops NaN and reshapes.

    Examples:

    >>> class Offset(BaseEstimator):
...     def fit(self, coords, data, weights=None): ...
...     def predict(self, coords): ...

    Trends and de-ramping¶

    Polynomial trends and per-epoch de-ramping (PRD F9, plan task T24).

    :class:Trend fits a 2D polynomial of the coordinates by weighted least squares, on coordinates centered and scaled for conditioning (the raw UTM values, near 10⁶, would make the normal matrix singular in float64 from degree 2). It is the simplest spatial model and a step of the GNSS tie.

    :func:deramp removes a polynomial ramp from every epoch of a stack. In the temporal-denoising study, per-epoch spatial de-ramping cut velocity scatter by 10 to 24%, more than any temporal filter. The fit only needs sums over pixels (the normal equations), so it stays lazy and exact; it runs on every stride-th pixel by default and the ramp is subtracted from the full grid chunk by chunk. Ramps are long-wavelength by construction: remove them only when long-wavelength signal (plate motion, large subsidence bowls) is not wanted, or mask such areas out of the fit.

    Gridders¶

    Gridders for point data (PRD F9, plan task T24.4).

    :class:Spline is the biharmonic spline of Sandwell (1987, https://doi.org/10.1029/GL014i002p00139): the field is a sum of Green's functions g(r) = r² (ln r - 1) centered on the data points, with forces from weighted least squares and optional damping (verde's Spline is the design reference, not a dependency). It suits smooth fields from scattered points (GNSS velocities, downsampled cells). The system is dense, n x n for n points, so keep n to a few thousand (downsample first).

    :class:Nearest copies the value of the nearest point with positive weight: a fallback with no smoothing.

    GNSS tie¶

    GNSS tie: remove long-wavelength DISP error with GNSS (PRD F9, plan task T33).

    The residual DISP minus GNSS at the stations is fitted with a smooth surface (a polynomial trend, optionally plus a damped spline) and the predicted field is subtracted from DISP, either for the velocity or for every epoch.

    What the tie field may hold. Only long-wavelength error: orbits, long-wavelength troposphere and ionosphere, reference-frame and plate-motion differences. Local deformation (groundwater subsidence, coseismic steps) must stay in the calibrated product, so stations in deforming areas are left out of the fit (exclude) and their signal is restored by construction: the smooth field does not reach it. A plane (degree=1) is the default; add the spline only with damping strong enough that its scale stays well above the station spacing. Leave-one-station-out scores improve as the field gets more local, partly by construction (a field that bends to each station predicts its neighbors well), so a better score alone does not show that the signal was preserved.

    apply_tie ¶

    apply_tie(ds: Dataset, tie: TieResult, *, layer: str = 'displacement') -> xr.Dataset

    Subtract a GNSS tie from layer.

    Epoch mode subtracts each epoch's correction (zero where no tie was fitted). Velocity mode subtracts the correction from a velocity layer, or from displacement as the corrected rate times the time since the first epoch.

    Examples:

    >>> corrected = apply_tie(ds, tie)

    cross_validate_tie ¶

    cross_validate_tie(comparison: Any, *, mode: Mode = 'velocity', degree: int = 1, damping: Optional[float] = None, exclude: Any = None) -> pd.DataFrame

    Leave-one-station-out: residual RMSE at each station before and after.

    Each station used in the fit is left out in turn, the tie is fitted on the others and predicted at it. Excluded stations are scored with the tie of all used stations (they never enter the fit).

    Returns:

    Type Description
    DataFrame

    Per station: rmse_before (of its residual) and rmse_after (after subtracting the prediction), excluded; attrs holds the network RMSE before and after (rmse_*), and the median of the per-station values (median_*). The RMSE is driven by single stations (local subsidence, a short record); the median describes the typical station.

    Examples:

    >>> scores = cross_validate_tie(comparison, mode="epoch")
>>> scores.attrs["rmse_before"], scores.attrs["rmse_after"]
>>> scores.attrs["median_before"], scores.attrs["median_after"]

    cross_val_score ¶

    cross_val_score(estimator: BaseEstimator, coords: Coords, data: Any, *, spacing: float, weights: Optional[Any] = None, n_splits: int = 5, seed: int = 0) -> np.ndarray

    Score an estimator with spatial block k-fold cross-validation.

    Points are grouped into square blocks of side spacing; the blocks are shuffled and split into n_splits folds. Each fold is predicted by a copy fitted on the other folds, and scored with the weighted R².

    Returns:

    Type Description
    ndarray

    One score per fold.

    Examples:

    >>> from disp_xr.models import Trend
>>> scores = cross_val_score(Trend(1), coords, data, spacing=5e3)
