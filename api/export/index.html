    Export¶

    Every writer records the disp-xr version, package versions, input granules and the history of operations in the output's attributes. to_geotiff writes Cloud Optimized GeoTIFFs; pass it the Dataset and a layer to keep that provenance.

    to_geotiff ¶

    to_geotiff(obj: Union[DataArray, Dataset], path: Union[str, Path], *, layer: str = 'displacement', per_epoch: bool = False, compress: str = 'DEFLATE', overwrite: bool = False) -> list[Path]

    Write a layer as a Cloud Optimized GeoTIFF (COG) with overviews.

    The file is tiled with internal overviews (GDAL adds them above 512 pixels), so it can be read in parts over HTTP. Its metadata holds the provenance: DISP_XR_VERSION, SOFTWARE_VERSIONS, INPUT_GRANULES and HISTORY.

    Parameters:

    Name Type Description Default
    obj DataArray or Dataset

    A (y, x) layer with a CRS, or (time, y, x) with per_epoch; or a Dataset, from which layer is written. Pass the Dataset to keep its provenance: input granules and history live in Dataset attributes.

    		 required
    layer str

    Layer to write when obj is a Dataset.

    		 'displacement'
    path str or Path

    Output file. With per_epoch, one file per epoch named <stem>_<YYYYMMDD>.tif next to it.

    		 required
    per_epoch bool

    Write each epoch of a (time, y, x) layer to its own file.

    		 False
    compress str

    GDAL compression.

    		 'DEFLATE'
    overwrite bool

    Replace existing files; by default any existing output is refused before anything is written.

    		 False

    Returns:

    Type Description
    list[Path]

    Files written.

    Raises:

    Type Description
    ValueError

    If the layer has no CRS, has the wrong dims, or one epoch is larger than config["max_load_bytes"].
    FileExistsError

    If an output file exists and overwrite is not set.

    Examples:

    >>> dxr.to_geotiff(ds.isel(time=-1), "last.tif")
>>> dxr.to_geotiff(velocity, "velocity.tif", layer="velocity")
>>> dxr.to_geotiff(ds, "epochs.tif", per_epoch=True)

    GeoZarr for bowser¶

    GeoZarr stores that bowser opens directly (PRD C4, plan task T27.9).

    to_geozarr(ds, store) writes a GeoZarr store: the multiscale pyramid of :func:disp_xr.to_pyramid (or one flat group), with CF and Zarr proj: / spatial: metadata on every level. profile="bowser" (the default) adds what bowser <https://github.com/opera-adt/bowser>_ uses to display the data, without changing anything a strict GeoZarr reader relies on:

    • display levels by factor 2 until the shorter side is under 256 cells (bowser picks the level whose pixel matches the tile pixel, so analysis factors such as 33 alone leave mid zooms reading 30 m);
    • bowser_uses_spatial_ref on every variable: true only for displacement and velocity. Otherwise bowser infers it from the units and subtracts a reference value from sigmas (meters) and inversion residuals (radians);
    • long_name on every variable (the colorbar title);
    • reference_lonlat from :func:disp_xr.rereference (a point reference), shown as the reference marker;
    • the line-of-sight attributes bowser reads (heading_angle_deg, incidence_angle_deg and los_enu_ground_to_satellite, near, center and far) from the static layers, when given;
    • bowser_histogram per epoch on level 0 (bins and percentiles), so the histogram panel does not read a full-resolution epoch per request;
    • float32 data, and chunks of one epoch by 256 x 256 in shards of 4 epochs by 1,024 x 1,024 (the "tiles" preset, bowser's tuned layout).

    Checked against bowser ops (0a61c6a; zarr 3.1.1, xarray 2025.8, rioxarray 0.19) with tests/bowser_check.py: the per-level proj: and spatial: attributes, the multiscales transform, consolidated metadata, spatial_ref as a coordinate, integer masks with a _FillValue (decoded to NaN) and one-chunk small levels do not change what bowser reads or shows.

    los_attrs ¶

    los_attrs(static: Dataset, look_side: Literal['right', 'left'] = 'right') -> dict[str, Any]

    Return bowser's line-of-sight attributes from the static layers.

    Near, center and far are the 5th, 50th and 95th percentiles of the incidence angle; the ENU vectors are rebuilt from those incidences and the median azimuth. The ground-track heading is the azimuth of the ground-to-satellite vector plus 90 degrees for a right-looking radar (Sentinel-1), minus 90 for a left-looking one.

    Parameters:

    Name Type Description Default
    static Dataset

    los_east and los_north (and los_up), as from :func:disp_xr.open_static.

    		 required
    look_side ('right', 'left')

    Radar look direction.

    		 "right"

    histogram_stats ¶

    histogram_stats(da: DataArray) -> list[dict[str, Any]]

    Return bowser's per-epoch histogram entries for one variable.

    One dict per epoch (one for a 2D layer) with 100 bins, the counts, the extremes and the 2/98, 16/84 and 2.275/97.725 percentiles, matching bowser's _compute_histogram_stats. Epochs are computed in parallel, each read once.

    Multiscale pyramids¶

    Multiscale pyramids of downsampled levels in Zarr (PRD C4, plan task T27.7).

    A pyramid is one Zarr group whose children are the levels, as sibling groups 0 (the input, 30 m), 1, 2, ... (each from :func:disp_xr.downsample of level 0). Every level is self-contained: CF spatial_ref, the Zarr proj: and spatial: attributes with its own spatial:transform and spatial:shape, and the provenance attributes. The root carries the multiscales layout: per level its asset, derived_from, the relative transform (scale = factor, translation 0, since cell edges start at the first pixel edge), the absolute spatial:transform and spatial:shape, the resampling method, and the reduction of each variable under disp_xr:resampling.

    The multiscales, spatial: and proj: conventions are at pilot maturity (multiscales v0.1, breaking changes expected before v1), so their ids and URLs live only in this module and the version is recorded in the root attributes. :func:open_pyramid finds levels from the layout, never from group names.

    Conventions: https://github.com/zarr-conventions/multiscales (v0.1), https://github.com/zarr-conventions/spatial, https://github.com/zarr-conventions/proj.

    build_overviews ¶

    build_overviews(ds: Dataset, factors: Sequence[int] = (33, 67, 333), **downsample_kwargs: Any) -> xr.DataTree

    Return a pyramid of ds and its downsampled levels as a DataTree.

    Parameters:

    Name Type Description Default
    ds Dataset

    Chained, re-referenced data at full resolution; level 0.

    		 required
    factors sequence of int

    		 (33, 67, 333)
    **downsample_kwargs Any

    Examples:

>>> dxr.to_pyramid(tree, "F11116_pyramid.zarr")

    open_pyramid ¶

    open_pyramid(store: Union[str, Path, Any], *, storage_options: Optional[Mapping[str, Any]] = None) -> xr.DataTree

    Open a pyramid written by :func:to_pyramid, lazily.
